# X-ray fracture scorecard

Written by `score.py` from `work/eval/xray/predictions.csv` and the two datasets' own index files.
Every number here is defined in [METRICS_SPEC.md](METRICS_SPEC.md) and is recomputed from that
document alone by `recompute.py`, written by an agent that has never seen `score.py`
(`recompute.log`). Do not edit this file by hand.

**The question:** does this radiograph show a fracture? One yes or no per image.

**Not a medical device.** rAidiology is for education and research, not for diagnosis or
treatment decisions (`LICENSING.md`).

## What the numbers are

| | |
|---|---|
| `grazpedwri` | GRAZPEDWRI-DX, 20,327 paediatric wrist radiographs of 6,091 patients, CC BY 4.0. Nagy, Janisch, Hrzic, Sorantin, Tschauner, Scientific Data 9, 222 (2022), doi:10.1038/s41597-022-01328-z |
| `fracatlas` | FracAtlas, 4,083 musculoskeletal radiographs (hand, leg, hip, shoulder), CC BY 4.0. Abedeen, Rahman, Prottyasha, Ahmed, Chowdhury, Shatabda, Scientific Data 10, 521 (2023), doi:10.1038/s41597-023-02432-4 |
| the split | 20% of units held out as test, 80% development in 5 folds, seed 20261001 (`split.json`). The unit is the **patient** for GRAZPEDWRI-DX. FracAtlas publishes no patient identifier, so there the unit is the **image**, and two radiographs of the same person could fall on both sides. That is why the ship decision rests on GRAZPEDWRI-DX |
| `prevalence` | always answers with the development majority: the floor |
| `meta` | logistic regression on age, sex, side, projection and scanner maker only, no pixels: the **no-image floor**. A detector that does not beat this has learned nothing from the image |
| `features` | logistic regression on classical image statistics (intensity, gradient and texture summaries over a fixed grid), no deep learning and no pretrained weights |
| `reader` | Claude Opus 5.5 reading the image, as sub-agents with no API key, on a sample of the split |
| `cnn` | the candidate: a small convolutional network trained from scratch on development folds only |
| the strata | `all`, plus `initial_exam`, `no_cast` and `certain` for GRAZPEDWRI-DX, and the body parts for FracAtlas. A plaster cast almost always means a fracture somebody already found, and most of these images are follow-ups, so a model can score well on the cast instead of the break. Nothing is thrown away; the subsets show it |
| the intervals | 95% percentile bootstrap, 2,000 resamples, resampling units, computed separately for every number |
| a miss | an in-scope image a method made no prediction for stays in n and is filled with the worst possible answer, so a method cannot score better by refusing the hard ones |

Development rows are out of fold: fold k is predicted by a model fitted on the other four, and every
threshold is fitted on the fitting folds only.
